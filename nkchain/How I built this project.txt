## System Architecture & Transaction Flow

### Ledger Mechanics & State Engine
ChainLedger enforces transactional integrity using pessimistic row locks and an explicit state machine:

- **Concurrency Protection**: During execution, PostgreSQL acquires an exclusive row lock on the sender's wallet record via `.with_for_update()` in `app/services/ledger_service.py` to prevent microsecond double-spend race conditions.

- **Dual Database Strategy**: Features an isolated production database alongside a dedicated testing database to ensure full test suite isolation without side effects.

- **Transaction Lifecycle State Machine**:

  - `PENDING`: Transaction initiated, awaiting on-chain confirmation or internal validation.

  - `COMPLETED`: Matching debit and credit entries posted atomically.

  - `FAILED`: Aborted due to insufficient funds, lock timeouts, or validation errors.

  - `REVERSED`: Explicitly refunded or rolled back without modifying historical entries.
